Dashboard design system

Design SystemsSaaS9 monthsShipped

Building a shared component library and the habits around it, so four product teams could ship consistent features twice as fast.

Role
Design system lead
Team
2 designers, 3 front-end engineers
Timeline
9 months · 2024
Tools
Figma, Storybook, Zeroheight
01

Overview The challenge

Four teams were building the same dashboard product in four slightly different ways. We had 14 button styles, 9 shades of grey and no shared language between design and engineering.

The goal: one source of truth that teams would actually want to use.

02

Audit Counting the chaos

I started with an interface inventory across every product surface, which turned a vague feeling of inconsistency into a very concrete (and slightly embarrassing) wall of screenshots.

  • Screenshotted and grouped 300+ UI elements across 4 products
  • Interviewed designers and engineers on every team about their pain points
  • Ran a workshop to agree on principles and naming
03

Build Tokens first, components second

We defined colour, type, spacing and motion tokens shared between Figma and code, then built components on top, so a single change could ripple everywhere.

  • Created a token system mapped 1:1 between Figma variables and CSS
  • Designed and documented 60+ components with every state
  • Paired with engineers to ship each component to Storybook
  • Wrote usage guidelines with do's and don'ts
We built the new reporting page in a week. Last time it took a month. Engineering lead, Team Analytics
04

Adoption Making it stick

A system nobody uses is just a nice Figma file. I set up fortnightly office hours, a contribution process and a Slack channel, and celebrated every team's first fully-system screen.

60+Components shipped
2×Faster feature delivery
92%Screens using the system
05

Reflection What I learned

Design systems are more about people than pixels. The biggest wins came from the rituals around the library, not the library itself.
